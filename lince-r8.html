LINCE

A screen is pixels; a pointer wants coordinates; the model in between sees a smaller picture of its own. LINCE reads a raw desktop screenshot offline — print, buttons, fields, icons — and hands back click zones in the frame the model says it sees, in whatever units the pointer takes. One file, no network, no model at runtime. The TRAIL keeps the walk you took through the screens, for the next model that drives. Served from a KVM, this page is also the hands: it photographs the screen through the KVM’s own capture and clicks through its USB.
PASTE · DROP · OR TAP TO CHOOSE A SCREENSHOT
Print Screen then Ctrl+V works. PNG or JPEG, any resolution — a KVM snapshot is fine. Give it the real screen at its real size: every pixel is read, and the answers are scaled to the model's frame. Nothing leaves this page.
KVM NOT CONNECTED

This page is being served by a KVM. CONNECT opens its event socket: the HDMI capture wakes up, and the pointer and keyboard are a message away. LOOK photographs the screen through the capture and reads it here — no screenshot on the box, no folder, nothing installed there. AUTO LOOK does that every few seconds. DRIVE is the loop closed by hand: with it on, tapping a zone on the screen below clicks it for real through the KVM, records it as a TRAIL step, and takes the next look — the walk gets recorded by walking it. Off, a tap only selects, as ever.

A script is the compiled walk. The box below is JavaScript run against L, this page’s KVM primitives: await L.look() reads the screen and returns its zones; L.zones() is the last read; L.find(/more$/i) the zones whose text matches (every zone carries kvmd:[X,Y]); await L.click(kx, ky) or await L.click(zone) clicks; L.key("Enter"), L.keys("MetaLeft","PrintScreen") for chords, L.type("text"), L.wheel(-3), await L.wait(ms), L.log(...), and L.stopped() goes true when STOP is pressed. RUN THE TRAIL loads the replay script. A model writes these; this page runs them with no model in the loop.

WATCH OFF

Pick the folder your screenshots land in — Win+PrintScreen saves to Pictures\Screenshots. Every PNG or JPEG that arrives from then on is read as it lands and answered four times over: its manifest (.txt) and JSON next to it under its own name, then lince-latest.txt and lince-latest.json, the JSON last of all. The pointer space is the one chosen below; KVMD is picked for you if none is. The trail (below) is written there too, as lince-trail.txt and lince-trail.json, whenever it changes. What was already in the folder is left alone. The page has to stay open; Chrome and Edge only. The same watch, headless: node cadena.js serve <folder> runs this engine from a shell on the box, with no browser to throttle, and serves the folder over HTTP as well.

The fixed names are for whatever waits. Every manifest written here opens with # seq: 7, # source: "Screenshot (16).png" and # time: 2026-11-07T07:41:12.345Z, and the JSON carries seq, source and time: a reader polls one path until seq moves, instead of listing the folder and guessing which file is newest. The count carries on from the lince-latest.json already in the folder, so it survives this page being closed and opened again. Each file lands whole — the browser writes a swap file and renames it on close — so nobody ever reads half of one.

The read side, from a shell. A connected folder reads these files as they are. For a script anywhere on your tailnet, the box serves the folder itself: one command, no code, HTTPS under the node’s own certificate, reachable only from inside the tailnet and under its ACLs — the same bridge the KVM already rides. Say which box and which folder, and copy. Or let cadena.js serve do the serving, plain HTTP on port 7890, and skip this.

# once, on the box: the folder, served to the tailnet (stays on until: tailscale serve reset)
tailscale serve --bg --set-path=/shots "C:\Users\you\Pictures\Screenshots"

# the newest manifest, from any node of the tailnet (lince-latest.json stands beside it)

A trail is the walk you took. Tap a zone on the screen above and ADD STEP; take the next screenshot; tap the next zone. Each step keeps the zone, its x,y and kvmd:X,Y, the screen it was on and the screen that came next — which is whatever screenshot arrives after it. Taps only: what a field wants typed is for whoever drives to decide on the day. Hand the trail to a model before it drives and it starts out knowing where things stand and what each tap leads to, instead of feeling its way; two walks through the same page are plenty. The same steps copy out as cadena.js links, to walk again as they are.

The trail stays with this page between visits. While a folder is watched it is written there too, as lince-trail.txt and lince-trail.json beside the manifests, so a shell on the tailnet reads it from the same place. Tap a step to choose it: its note is yours to write below, DROP STEP lets it go (tap twice), and if it was taken on the screen now showing, its zone lights up there.

FOR MACHINES the same file is a command

This page is also a Node script. A model with a shell and a KVM snapshot needs no browser. Give it the capture at its real size, and say the size of your own screenshot of that screen — only you know it:

node lince.html shot.png --frame 1456x819       the manifest, in the frame you click in: your own screenshot's size
node lince.html shot.png --frame mine.png       the same, read off a picture: your own screenshot
node lince.html shot.png                        no frame said: one is assumed, and the answer says ASSUMED
node lince.html shot.png --frame capture        in the capture's own pixels
node lince.html shot.png --out frame.png        and the frame as a picture: what you see is what you click
node lince.html shot.png --zoom 100,55,200,115 --out zoom.png
                                                look closer at that box: x,y stay full-frame
node lince.html shot.png --zoom 37              the same, around zone 37
node lince.html shot.png --find "Compose"       best match first line as: x y
node lince.html shot.png --at 148,82            what stands at that point of the frame
node lince.html shot.png --space kvmd           each line also as the KVM takes it: kvmd:X,Y
node lince.html shot.png --space capture        each line also in real pixels: px:X,Y
node lince.html --frame 1456x819 --at 148,82 --space kvmd
                                                no image: one frame point into pointer units
node lince.html --help                          all options

The frame is declared, never guessed in silence. A harness decides what size of picture its model is handed, and two harnesses give two sizes for the same screen. So the size comes from the model's side: --frame WxH, a picture of that size, or LINCE_FRAME=WxH in the environment, said once for a whole session. Where nobody says, the usual frame under a 1568 px picture limit stands in and the second line of the answer reads ASSUMED, with the sum that puts it right.

Zoom to identify, click in full-frame. A zoom is cut from the capture's own pixels and drawn as large as a model can be shown; its rulers read full-frame x and y, and each zone carries its manifest number. The model looks at the zoom to see which icon is which, then clicks with the frame coordinates it already had. It never counts in real pixels and never in the zoom's own.

The loop closes over the tailnet. Through the KVM a model presses Win+PrintScreen; on the box the screenshot lands in the watched folder and this page (or cadena.js serve) answers it, lince-latest.txt and then lince-latest.json last. With the folder served by tailscale serve (WATCH, above) or by cadena.js serve, any shell on the tailnet polls that one URL until # seq: moves, reads the new manifest, and sends its kvmd:X,Y back through the KVM. cadena.js is that shell's side of the chain: look, click, type, key, one command per link. Read side and act side ride one bridge; nothing runs on the box but this page or its headless twin.

A trail goes ahead of the model. Steps tapped out on this page — zone, x,y, kvmd:X,Y, the screen each was on and the one that came next — stay with the page and, while a folder is watched, are written beside the manifests as lince-trail.txt and lince-trail.json: a shell reads them from the same URL as the manifests, before it drives. A screen is named after its screenshot, which stands in the folder with its own manifest; zone numbers belong to that screen alone, so a model matches by label and place. In a page, LINCE.trail.text(), .json() and .links() are the same three forms, .add() takes the step the page has selected, and dataset.trail holds the step count.

On a KVM, the page is the hands too. Dropped into the KVM’s web root (/usr/share/kvmd/web/lince.html on a PiKVM or GL-KVM) it is served same-origin with the KVMD API: a WebSocket on /api/ws wakes the capture and carries HID, /api/streamer/snapshot is a JPEG of the screen at the HDMI’s own resolution, and the login cookie covers both. LINCE.kvm exposes look, zones, find, click, key, keys, type, wheel, wait, log, stopped and run(source); dataset.kvm is on while the socket is open. Nothing runs on the target machine at all.

In a page, the engine is window.LINCE: await LINCE.fromBlob(blob) returns the zones, LINCE.manifest(result, {frame:[1456,819], space:"kvmd"}) the text, LINCE.find(result, "Compose", {frame:[1456,819]}) the point, LINCE.at(result, [148,82], {frame:[1456,819]}) what stands there, LINCE.picture(result, {frame:[1456,819], zoom:[100,55,200,115]}) the pixels to look at; stamp:{seq:7, source:"Screenshot (16).png", time:"…"} in the options puts those three header lines on a manifest, and the fields on the JSON. The page takes the same words on its address: #frame=1456x819&space=kvmd&zoom=100,55,200,115. document.documentElement.dataset.state goes idle → busy → done, dataset.frame holds the frame in use and dataset.frameSaid whether it was declared or only assumed, dataset.seq the seq of the last manifest WATCH wrote, and the manifest sits in #out.

Reading is deterministic: the same pixels give the same zones, and the same zone numbers. Small print under about 7 px cap height, print laid over photographs, and print cut off by a window edge are left alone rather than guessed — which is why the capture should be the real screen and not the model's small frame of it.

Node runs the file as plain CommonJS. Inside a project whose package.json says "type": "module" it refuses the .html name: copy the file to lince.cjs and run that.
